**F1 — Gate executable harness configuration before discovery.** [harness.ts](../../opencode/packages/core/src/harness.ts#L330) launches `settings.binaryPath` with workspace-controlled arguments and working directory. [Config](../../opencode/packages/core/src/config.ts#L180) discovers repository configuration, and `configuredInstances` accepts its `harnesses` entries without distinguishing trusted/global configuration. Opening the composer calls [harness discovery](../../opencode/packages/app/src/components/prompt-input/harness-controller.ts#L35), whose Codex availability probe launches the configured binary even before a prompt is submitted. An attacker-controlled workspace can therefore supply an executable to run with the server process's privileges. The existing plugin restrictions do not cover this V2 path. The isolated check supplied a workspace document and recorded its binary reaching the spawn boundary; it executed no process. Restrict executable settings to trusted user configuration, or require a persisted workspace trust decision before both probing and launching. Introduced with `0552fe1`.

**F2 — Preserve the editor's ETag when checking Calendar conflicts.** [google-calendar.ts](../../opencode/packages/desktop/src/main/google-calendar.ts#L425) replaces the submitted event's ETag with the ETag from a fresh GET. DELETE does the same at line 414. If another client changes the event after this editor loaded it, the stale form is applied to the latest version instead of reporting a conflict. The check submitted `local-v1` and observed `If-Match: remote-v2`. Keep the new authoritative participant/recurrence validation, but also compare the editor's version against the fetched resource before using its version for the final write. Google's [conditional modification documentation](https://developers.google.com/workspace/calendar/api/guides/version-resources) describes the previous-retrieval ETag as protection against lost modifications. This regression is in the current uncommitted audit remediation; HEAD previously used `input.event.etag`.

**F3 — Do not replace an edited draft with an earlier save response.** [notes.tsx](../../opencode/packages/app/src/pages/notes.tsx#L258) calls `applyDocument` when the write finishes. The editor stays editable during that write: only `loadedNote.loading` is passed as its loading state. Typing after clicking Save is then overwritten by the earlier response, and `baseBody` is reset too, making the lost draft appear saved. The check paused the write, entered newer text, then resolved the request and observed the newer text disappear. Save the submitted snapshot as the baseline while retaining subsequent edits, or disable editing for the write duration. Apply the same rule to title/tags/project fields. This behavior comes from the notes editor added in `0552fe1`; the current local-summary optimization does not fix it.

**F4 — Guard in-app navigation while drafts are dirty.** [notes.tsx](../../opencode/packages/app/src/pages/notes.tsx#L173) only registers `beforeunload`, which does not guard Solid Router navigation. Notes blocks its own note/workspace picker, but the [shared sidebar](../../opencode/packages/app/src/components/second-brain-sidebar.tsx#L30) calls `navigate` directly. Clicking Projects/Calendar/Activity unmounts Notes and loses its component-local draft; returning reloads the stored file. [Projects](../../opencode/packages/app/src/pages/projects.tsx#L117) similarly checks dirty state for some local actions without registering a route-leave guard. Use the router's existing leave interception or preserve drafts outside the page. Source-confirmed; not exercised in a running browser.

**F5 — Forward every newly admitted steering message.** [harness.ts](../../opencode/packages/core/src/harness.ts#L791) sends only `findLast(role === "user")` to an existing Codex thread. The [session runner](../../opencode/packages/core/src/session/runner/llm.ts#L201) promotes all eligible steering inputs together; [promoteSteers](../../opencode/packages/core/src/session/input.ts#L245) does not limit the batch to one. When two follow-ups arrive during an active turn, both become visible canonical messages, but only the last reaches Codex. The check passed two consecutive new user messages and received only the second. Track the last forwarded message boundary and deliver every unseen input exactly once. The latest-message selection dates to `0552fe1` and remains in the persistent-thread/handoff flow.

**F6 — Treat a lost task-create response as an uncertain outcome.** [google-calendar.ts](../../opencode/packages/desktop/src/main/google-calendar.ts#L489) sends a normal Google Tasks POST. If Google commits that request but the response is lost, the operation becomes `offline`, and `retryTaskOutbox` sends another POST. The local idempotency key is not included in a provider deduplication mechanism. The check simulated that response loss and observed two POSTs for the same key. Google documents [tasks.insert](https://developers.google.com/workspace/tasks/reference/rest/v1/tasks/insert) as creating a new task. Add reconciliation for uncertain outcomes, or surface them for resolution instead of automatically replaying a create. This differs from event creation, which already derives a stable provider event ID. Present since `cea5afd`; no real Google task was created in this review.

**F7 — Send attachment content through the Codex transport.** [harness.ts](../../opencode/packages/core/src/harness.ts#L802) replaces every media part with `[Attached filename]`. The transport then sends [one text input](../../opencode/packages/core/src/harness.ts#L480). An uploaded image can appear in the conversation while Codex receives neither its bytes nor a usable URI. The check reduced a media part containing a data URL to a filename label. Map supported media to the harness input format and reject unsupported attachments visibly before submission. Introduced with `0552fe1`.

**F8 — Reconcile pending task identities after outbox success.** [calendar.tsx](../../opencode/packages/app/src/pages/calendar.tsx#L401) preserves local outbox entries whose provider IDs do not occur in the fetched result. A queued creation has a `pending:...` ID, while Google returns a newly assigned ID. The merge therefore keeps the offline placeholder and adds a separate synced task; the real task also misses local project/scheduling fields because those are matched by provider ID. The check produced two tasks after one successful queued creation. Expose settled outbox results keyed by idempotency key and replace the pending identity while preserving local fields. Present in the planner integration.

**F9 — Remember transport failure and reject future requests.** [codex-app-server.ts](../../opencode/packages/core/src/harness/codex-app-server.ts#L53) fails only the requests pending at the moment of EOF. A later [request](../../opencode/packages/core/src/harness/codex-app-server.ts#L169) creates a fresh Deferred and waits for a response from the exited process. The cached Codex runtime can survive an idle subprocess exit, so the next prompt reaches this path without a request timeout. The check waited for the actual client's EOF error, issued a new request, and observed it remain unresolved until an external test timeout. Store the terminal transport error, fail new requests immediately, and allow the runtime to be discarded/reopened. Introduced with `0552fe1`.

**F10 — Never evict unfinished outbox operations to enforce a size cap.** [persistOutbox](../../opencode/packages/desktop/src/main/google-calendar.ts#L622) and [persistTaskOutbox](../../opencode/packages/desktop/src/main/google-calendar.ts#L636) keep only the last 100 entries, regardless of status. Queuing write 101 while offline removes the oldest pending write from durable storage, although the UI can still show it as pending. The check passed 101 offline operations to each production function and observed the oldest disappear. Prune completed history first; reject additional writes explicitly if the pending queue is full. Present since `cea5afd`.

**F11 — Carry the brain workspace through project shortcuts.** [projects.tsx](../../opencode/packages/app/src/pages/projects.tsx#L322) navigates using only a project ID. The destinations independently choose their initial directory from `layout.home.selection()` or the first workspace. With home set to A, select B in Projects and open its notes or calendar: the destination can load A and filter it by B's project ID. The source selector does not update the shared selection. Carry the source brain directory in the navigation state/query and validate it against available workspaces. Source-confirmed; not exercised in a running browser.

**F12 — Preserve harness settings when migrating legacy configuration.** [config.ts](../../opencode/packages/core/src/config.ts#L161) routes any document with a legacy key such as `permission` or `provider` through V1 decoding and migration. The [migration](../../opencode/packages/core/src/v1/config/migrate.ts#L35) does not carry `harnesses` forward. Adding a custom binary/model or `enabled: false` to an existing OpenCode configuration silently loses that setting and leaves the built-in defaults. The check confirmed that a document with `permission: {}` and a disabled Codex instance is classified as V1 and loses `harnesses`. Preserve the new field through V1 decoding/migration, with a mixed-config check. This is an integration gap introduced when harness configuration was added in `0552fe1`.
